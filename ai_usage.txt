- Розширив lexer.py (Task 1/2/3 потребують нових токенів): додав
  ключові слова struct/fn до KEYWORDS. "." і "," стали однобайтовими
  операторами поряд із "+"/"*". "(" і ")" отримали окремий вид токена
  "paren" (а не "operator" чи "block") — так виклик функції ніколи не
  сплутати з блоком "{"/"}" чи навпаки. "->" вимагає одного байта
  зчитування наперед, щоб відрізнити його від самотнього "-" — за тим

- Розширив ast_nodes.py: ProgramNode тепер несе structs/fns окремо від
  statements (і друкує їх у dump() у цьому порядку). StructNode тримає
  fields як список кортежів (type_name, mutable, name, line, col) —
  checker.py дозаповнює field_index/field_type/field_mut/field_order
  після перевірки. FnNode тримає params так само кортежами і body як
  BlockNode (той самий клас, що й у if/while). ParamNode — аналог
  DeclNode для параметра: той самий інтерфейс (type_name/name/mutable),
  mutable завжди False, бо "Parameters are copies and cannot be changed
  in the body" — це дозволило checker.py/gen.py працювати з параметром
  і локальною змінною через один і той самий код (self.scopes,
  self.ptrs), без спеціальних гілок. InitNode — вузол ініціалізатора
  decl: items — список значень, кожне або вираз, або вкладений InitNode
  (додаткове завдання, вкладені {}). FieldNode (ланцюжок читання
  x.y.z) і CallNode — нові факти. AssignNode отримав третє поле
  fields — список полів після базового імені (порожній для звичайного
  "x := e").
- Переписав parser.py: parse_program тепер відстежує фазу
  structs -> fns -> statements і відкидає struct/fn, що зустрівся після
  пізнішої фази, рівно в тому рядку. parse_struct/parse_field_decl/
  parse_fn/parse_param — нові однорядкові/багаторядкові правила за
  зразком існуючого parse_block (struct і fn тіла — такі самі
  багаторядкові конструкції, як if/while, з тим самим кursором рядків).
  Найделікатніша зміна — parse_statement: рядок, що починається з
  ідентифікатора, тепер може бути (a) decl зі структурним типом
  ("Point p{10, 20}"), (b) assign ("x := e" або "x.y.z := e"), (c)
  самотній виклик ("f(1)" — синтаксична помилка, "a call cannot stand
  alone as a statement"). Розрізняється одним токеном зчитування
  наперед (peek_next): другий токен ідентифікатор/"mut" -> decl;
  інакше -> parse_assign, яка сама або знаходить ":=" (можливо, після
  ланцюжка ".field"), або натикається на "(" і кидає помилку "call
  alone". Так само parse_factor: ідентифікатор + "(" -> виклик,
  ідентифікатор + "." -> ланцюжок полів (FieldNode), інакше — звичайна
  змінна. parse_init/parse_init_item рекурсивно читають
  "{" item {"," item} "}", де item — вираз або знову вкладені "{}"
  (додаткове завдання) — жодного окремого синтаксису для "звичайного"
  decl і decl зі структурою, все проходить крізь один InitNode.
- Переписав checker.py (Task 1/2/3): додав дві нові таблиці поряд зі
  стеком фреймів Practice 5 — self.structs (ім'я -> StructNode,
  field_index/field_type/field_mut/field_order рахуються тут же,
  "семантичний прохід знаходить індекс") і self.functions (ім'я ->
  FnNode, усі сигнатури збираються одним проходом перед перевіркою
  жодного тіла — за методичкою "first collect all the signatures, then
  check and generate the bodies" — це дозволяє функції викликати себе
  або функцію, оголошену нижче). declare_struct перевіряє, що тип поля
  — вбудований або вже є в self.structs (тобто оголошений вище —
  інакше про цикл/самовкладеність і дбати не треба, вона структурно
  неможлива: якщо type_name == struct.name, це найбільш конкретна
  помилка "cannot contain itself", перевіряється раніше за загальну
  "unknown type"). check_fn_body підміняє self.scopes на свіжий стек з
  одним фреймом параметрів (тіло не бачить змінних верхнього рівня) і
  виставляє self.current_fn на час перевірки тіла — це і прапорець для
  visit_exit (на верхньому рівні exit вимагає вбудованого типу, в
  тілі функції — типу результату, з тим самим звуженням i32->i64, що
  і скрізь), і джерело result_type для цієї перевірки.
  resolve_chain — одна функція для читання (visit_field) і запису
  (visit_assign) ланцюжка x.y.z: іде по полях, на кожному кроці
  шукає структуру за поточним типом і індекс поля в ній (checker, а не
  gen, шукає по імені — рівно та вимога з методички), при
  require_mut=True падає на першому не-mut ланці (сама база або будь-
  яке поле по дорозі) — приклад з методички "c.center.x := 25 # error:
  center is const, even though c and x are mut" перевірено буквально
  (tests/err/write_through_const_link.txt). is_fully_mut — окрема
  перевірка саме для цілісної заміни об'єкта через ":=" без ланцюжка:
  рекурсивно дивиться, чи всі поля структури (і структурні поля їхніх
  структур) mut — "so := can replace a whole mut object only if all
  its fields, at every depth, are mut" з методички; без цієї перевірки
  можна було б замінити цілий об'єкт з немутабельним полем просто
  тому, що сама змінна mut, що суперечить методичці. check_init
  перевіряє InitNode проти очікуваного типу: для вбудованого типу —
  рівно одне значення без вкладених "{}"; для структури — або одне
  значення типу самої структури (копіювання цілого об'єкта), або рівно
  стільки значень, скільки полів, кожне звіряється з типом свого поля,
  рекурсивно для вкладених InitNode (додаткове завдання). Повідомлення
  про невідповідність типу параметризовані рядком what ("initialise
  'x'", "initialise field 'radius' of 'Circle'", "assign to
  'c.radius'", "exit the function 'boolFn'", "pass argument 1 to
  'add'") так, що й найпростіший decl вбудованого типу читається
  рівно так само, як до появи структур.
- Переписав gen.py (Task 1/2/3): CodeGen тепер створюється окремо на
  кожне тіло функції (свій builder, свій self.ptrs) і окремо для
  верхнього рівня (той, що працює в main) — прапорець is_top_level

  з ланцюжком індексів, які вже знайшов checker (field.indices) —
  один gep замість кількох проходить крізь вкладені структури напряму
  (перевірено на Circle.center.x через дворівневий gep). Структурне
  значення — завжди ціле значення (first-class aggregate): параметр
  зі структурою копіюється по значенню в alloca на вході функції,
  повернення структури — load з alloca в ret, цілий об'єкт — load +
  store без жодного проходу по полях. Вкладений "{}" (додаткове
  завдання) будує одне агрегатне значення знизу вгору ланцюжком
  insert_value, перш ніж воно взагалі потрапляє в пам'ять (gen_init_value
  рекурсивний, той самий метод для верхнього decl і для вкладеного
  InitNode).
